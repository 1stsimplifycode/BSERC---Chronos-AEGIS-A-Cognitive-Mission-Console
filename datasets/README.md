# datasets/ -- Simulation and Evaluation Data

Holds data generated by the Mission Digital Twin (`digital_twin/`, Section
15) and the Evaluation Framework (`evaluation/`, Section 17).

`.gitignore` excludes `datasets/raw/` and `datasets/generated/` so large
generated artifacts are never committed directly -- `scripts/` regenerates
them reproducibly instead (fixed seeds, so re-running produces the same
data).

## `datasets/generated/`

Populated by running `python -m scripts.reproduce_all` (recommended --
see `docs/reproducibility-guide.md`), or each experiment script
individually:

- `rq12_cyber_metrics_summary.json` -- `evaluation.aggregate.ScenarioSummary`
  objects (canonical scenarios and, since Phase 8, the five firmware
  scenarios side by side), as produced by
  `evaluation.aggregate.write_summary_json`.
- `rq6_rq7_memory_retrieval_precision.json` -- (Phase 8) a before/after
  comparison: episode counts, precision@1 under categorical-fields-only
  vs. +incoming-edge-confidence similarity, the majority-class baseline,
  and the outcome distribution over every episode `EpisodicMissionMemory`
  stored during that run.
- `benchmark_report.json` (Phase 8) -- a full `benchmarks.report.BenchmarkSuiteReport`:
  scenario summaries, k-hop/memory-size scalability, continual-learning
  convergence, retrieval accuracy, and scheduler-calibration results. See
  `docs/benchmark-guide.md`.
- `ablation_report.json` (Phase 8) -- `evaluation.ablation.AblationReport`:
  the No-EMM ablation's measured metric differences.
- `reproducibility_report.json` (Phase 8) -- seeds used, a deterministic
  content hash for verifying two runs match, and which optional
  dependencies (scipy, matplotlib) were present.
- `publication/summary_tables.md` (Phase 8) -- Markdown tables generated
  from the above, plus `trust_evolution.png` / `metric_dashboard.png` if
  matplotlib is installed.

Every field in every file is a real, computed value -- see
`evaluation/README.md`, "What has actually been run," for the specific
findings from the last real run of each script, and for what these
numbers do and do not claim.

`digital_twin.dataset.MissionRecord` (CSV/JSON, via `write_csv`/
`write_json`) is the more general per-query-time reproducibility dataset
format any scenario run produces; the two files above are
`evaluation`-level aggregates built on top of it, not a replacement for it.

Nothing in `tests/` depends on this directory: tests use small, in-memory
fixtures (hand-built graphs, or `digital_twin` scenarios run fresh inside
the test), never a checked-in or previously-generated dataset file.
